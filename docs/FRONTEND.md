# راهنمای فرانت‌اند پنل — برای علی

این سند هر چیزی که برای ساختن پنل لازم است را توضیح می‌دهد: صفحه‌ها، اینکه هر صفحه کدام API را صدا می‌زند، حالت‌هایی که باید نمایش داده شوند، و خطاها.
بک‌اند کامل است؛ هر صفحه‌ای که این‌جا آمده، API آماده و تست‌شده دارد.

- مستندات تعاملی همه‌ی endpointها (با امکان امتحان کردن): `http://localhost:8000/docs`
- اسکیمای ماشینی API: [`docs/openapi.json`](openapi.json) — برای ساختن خودکار تایپ‌های TypeScript (بخش ۹)

## ۲. قواعد کلی API

| موضوع | قاعده |
|---|---|
| آدرس پایه | همه‌ی مسیرها زیر `/api/v1` |
| احراز هویت | هدر `Authorization: Bearer <access_token>` |
| فرمت | JSON، به جز آپلود فایل (`multipart/form-data`) |
| تاریخ‌ها | ISO 8601 به وقت UTC (مثل `2026-09-23T10:15:00Z`). برای نمایش شمسی، سمت فرانت تبدیل کن |
| شناسه‌ها | UUID به شکل رشته |
| قیمت‌ها | عدد صحیح به **تومان** |

### خطاها

همه‌ی خطاها این شکل را دارند و متن `detail` **فارسی و آماده‌ی نمایش به کاربر** است:

```json
{ "detail": "رمز عبور فعلی اشتباه است" }
```

استثنا: خطای **422 اعتبارسنجی خودکار** (مثلاً ایمیل نامعتبر) که `detail` یک لیست است:

```json
{ "detail": [{ "loc": ["body", "password"], "msg": "String should have at least 8 characters", "type": "string_too_short" }] }
```

برای این حالت از `loc` بفهم کدام فیلد مشکل دارد و پیام فارسی خودت را کنار همان فیلد نشان بده.

| کد | معنی | کار فرانت |
|---|---|---|
| 400 | درخواست منطقی نیست | نمایش `detail` |
| 401 | توکن نامعتبر یا منقضی | یک بار refresh (بخش ۳)، اگر نشد → صفحه‌ی ورود |
| 404 | پیدا نشد (یا مال فروشگاه دیگری است) | نمایش `detail` |
| 409 | تکراری (ایمیل ثبت‌شده) | نمایش `detail` |
| 413 | فایل یا حجم اطلاعات بیش از سقف | نمایش `detail` |
| 422 | داده نامعتبر (رشته‌ای یا لیستی، بالا را ببین) | نمایش کنار فیلد |
| 502 | سرویس هوش مصنوعی جواب نداد | «دوباره امتحان کنید» |

## ۳. ورود، ثبت‌نام و مدیریت توکن

| کار | درخواست | پاسخ |
|---|---|---|
| ثبت‌نام | `POST /auth/register` با `{email, password, full_name?, shop_name}` | `{access_token, refresh_token}` (201) |
| ورود | `POST /auth/login` با `{email, password}` | همان |
| تمدید | `POST /auth/refresh` با `{refresh_token}` | توکن‌های جدید |
| اطلاعات کاربر | `GET /me` | `{id, email, full_name, shop: {...}}` |

- رمز حداقل ۸ کاراکتر. ایمیل تکراری → 409.
- عمر `access_token` ۳۰ دقیقه و `refresh_token` ۳۰ روز است.
- الگوی پیشنهادی: همه‌ی درخواست‌ها از یک تابع `api()` رد شوند. اگر 401 گرفت، **یک بار** `/auth/refresh` را صدا بزند، توکن‌ها را ذخیره کند و درخواست اصلی را تکرار کند. اگر refresh هم 401 داد، کاربر را به صفحه‌ی ورود بفرستد. (اگر چند درخواست هم‌زمان 401 گرفتند، فقط یک refresh انجام شود.)

## ۴. صفحه‌ها

ترتیب پیشنهادی ساخت همین ترتیب است.

### ۴.۱ داشبورد (صفحه‌ی اصلی بعد از ورود)

`GET /dashboard`

```json
{
  "open_handoffs": 1,
  "setup": {
    "instagram_connected": true,
    "instagram_active": true,
    "instagram_username": "mahsa.boutique",
    "knowledge_entries": 6,
    "products_connected": true,
    "product_count": 5,
    "product_error": null,
    "ai_ready": true,
    "bot_enabled": true
  },
  "last_7_days": { "conversations": 3, "customer_messages": 5, "bot_replies": 4, "open_unanswered": 2 },
  "tokens_this_month": 3760
}
```

**چک‌لیست راه‌اندازی** از روی `setup` ساخته می‌شود. تا همه‌ی مراحل انجام نشده، بالای داشبورد نمایش داده شود:

| مرحله | انجام‌شده وقتی | لینک به |
|---|---|---|
| اتصال اینستاگرام | `instagram_connected && instagram_active` | صفحه‌ی اینستاگرام |
| وارد کردن اطلاعات فروشگاه | `knowledge_entries > 0` | صفحه‌ی اطلاعات |
| اتصال محصولات (اختیاری) | `products_connected` | صفحه‌ی محصولات |
| امتحان ربات | (سمت فرانت: بعد از اولین پیام در صفحه‌ی تست) | صفحه‌ی تست |
| روشن کردن ربات | `bot_enabled` | کلید روشن/خاموش |

**هشدارها** (بالای صفحه، با رنگ هشدار):
- `instagram_connected && !instagram_active` → «دسترسی به اینستاگرام قطع شده. دوباره وصل کنید.» + دکمه‌ی اتصال
- `product_error` مقدار دارد → نمایش همان متن + لینک به صفحه‌ی محصولات
- `ai_ready == false` → «هوش مصنوعی هنوز فعال نشده؛ ربات فعلا فقط پیام پیش‌فرض می‌فرستد.» (این مورد تنظیم سرور است، نه کار کاربر)

**کلید روشن/خاموش ربات**: `PATCH /shop` با `{"bot_enabled": true}`.
پیشنهاد: قبل از روشن کردن، اگر اینستاگرام وصل نیست یا اطلاعاتی وارد نشده، تأیید بگیر.

**کارت «منتظر جواب شما»:** اگر `open_handoffs > 0`، بالاترین و پررنگ‌ترین چیز داشبورد باشد:
«۲ مشتری منتظر جواب شما هستند» + دکمه به صفحه‌ی «ارجاع‌شده به شما» (بخش ۴.۷).

`open_handoffs` را روی لینک «ارجاع‌شده به شما» و `last_7_days.open_unanswered` را روی لینک «سوال‌های بی‌جواب» در منو به صورت badge نشان بده.

### ۴.۲ اتصال اینستاگرام

| کار | درخواست |
|---|---|
| وضعیت | `GET /instagram` → `{connected, active, username, ig_user_id, token_expires_at}` |
| گرفتن لینک اتصال | `GET /instagram/connect-url` → `{url}` |
| قطع اتصال | `DELETE /instagram` (204) |

**جریان اتصال:**
1. قبل از دکمه، راهنمای کوتاه نشان بده: پیج باید **Professional** (Business یا Creator) باشد و در اینستاگرام: Settings ← Messages and calls ← Connected tools ← **Allow access to messages** روشن باشد.
2. کاربر روی «اتصال اینستاگرام» می‌زند → `GET /instagram/connect-url` → `window.location.href = url`
3. کاربر در صفحه‌ی اینستاگرام اجازه می‌دهد؛ بک‌اند اتصال را کامل می‌کند.
4. بک‌اند مرورگر را به صفحه‌ی **`/instagram/callback`** در پنل برمی‌گرداند. **این صفحه را باید بسازی.** پارامترهای URL:

| `status` | `reason` | پیام |
|---|---|---|
| `connected` | — | «پیج با موفقیت وصل شد» → برو به صفحه‌ی بعدی چک‌لیست |
| `denied` | — | «اجازه‌ی دسترسی داده نشد» + دکمه‌ی تلاش دوباره |
| `error` | `account_in_use` | «این پیج به حساب دیگری وصل است» |
| `error` | `invalid_state` | «لینک منقضی شده، دوباره تلاش کنید» |
| `error` | `instagram` یا `missing_code` | «خطا در ارتباط با اینستاگرام، دوباره تلاش کنید» |

> لینک اتصال ۱۵ دقیقه اعتبار دارد؛ هر بار روی دکمه کلیک شد، لینک تازه بگیر (کش نکن).

### ۴.۳ اطلاعات فروشگاه

فرم را **از روی API بساز**، نه به صورت ثابت در کد:

`GET /knowledge/sections`

```json
{
  "sections": [
    { "key": "about", "label": "معرفی فروشگاه", "hint": "...", "placeholder": "مثال: ...", "multiple": false },
    { "key": "shipping", "label": "ارسال", "hint": "...", "placeholder": "...", "multiple": false },
    { "key": "faq", "label": "سوال‌های پرتکرار", "hint": "...", "placeholder": "...", "multiple": true },
    { "key": "file", "label": "فایل‌های آپلودشده", "hint": "...", "placeholder": "", "multiple": true }
  ],
  "supported_file_types": [".csv", ".docx", ".jpeg", ".jpg", ".md", ".pdf", ".png", ".txt", ".webp"],
  "max_file_bytes": 5242880,
  "char_limit": 40000
}
```

`GET /knowledge` → `{entries: [...], chars_used, char_limit}` (هر entry: `{id, section, title, content, source_filename, created_at, updated_at}`)

دو نوع بخش داریم:

**بخش‌های تکی** (`multiple: false`): about، shipping، payment، returns، contact
- یک textarea برای هر کدام. مقدار فعلی = entry با همان `section` (اگر وجود ندارد، خالی)
- ذخیره: `PUT /knowledge/single/{section}` با `{"content": "..."}`
- محتوای خالی = پاک کردن آن بخش (پاسخ `null`)

**بخش‌های چندتایی** (`multiple: true`): faq، free_text، file
- لیست کارت‌ها؛ برای faq، `title` = سوال و `content` = جواب
- افزودن: `POST /knowledge` با `{section, title, content}` (201)
- ویرایش: `PATCH /knowledge/{id}` با `{title?, content?}`
- حذف: `DELETE /knowledge/{id}` (204)

**آپلود فایل:** `POST /knowledge/upload` با `multipart/form-data` و فیلد `file`
- پاسخ: یک entry جدید در بخش `file` با متن استخراج‌شده. **متن را بلافاصله در حالت ویرایش نشان بده** تا کاربر بتواند اشتباهات را اصلاح کند (مخصوصاً برای عکس و PDF).
- این کار ممکن است چند ثانیه طول بکشد (برای عکس تا حدود ۳۰ ثانیه)؛ حالت loading لازم است.
- خطاها (422) متن فارسی دارند: فرمت پشتیبانی نمی‌شود، PDF اسکن‌شده، عکس وقتی هوش مصنوعی فعال نیست، ...
- قبل از ارسال، حجم فایل را با `max_file_bytes` چک کن.

**نوار مصرف:** `chars_used / char_limit` را به صورت progress bar نشان بده. رسیدن به سقف → 413.

### ۴.۴ محصولات

`GET /products/source`

```json
{
  "connected": true,
  "kind": "google_sheet",
  "url": "https://docs.google.com/spreadsheets/d/.../edit",
  "column_mapping": { "name": "نام محصول", "price": "قیمت" },
  "product_count": 5,
  "last_synced_at": "2026-09-23T09:57:00Z",
  "last_error": null
}
```

**اگر وصل نیست**، یک ویزارد سه‌مرحله‌ای:

**مرحله ۱ — انتخاب منبع**
- گزینه‌ی پیشنهادی: **گوگل شیت** (موجودی خودکار هر ۵ دقیقه به‌روز می‌شود)
- گزینه‌ی دوم: آپلود فایل Excel یا CSV (به‌روز نمی‌شود؛ برای تغییر باید دوباره آپلود کرد)
- لینک دانلود قالب آماده: `GET /products/template.csv` — بدون لاگین کار می‌کند، پس مستقیم با یک `<a href>` لینکش کن
- راهنمای گوگل شیت: دکمه‌ی Share ← General access ← **Anyone with the link** ← Viewer ← Copy link

**مرحله ۲ — پیش‌نمایش**
- گوگل شیت: `POST /products/sheet/preview` با `{"url": "..."}`
- فایل: `POST /products/file/preview` با `multipart` و فیلد `file`
- پاسخ:

```json
{
  "headers": ["نام کالا", "رنگ", "سایز", "قیمت (تومان)", "موجودی"],
  "sample_rows": [{ "نام کالا": "مانتو کتان", "رنگ": "مشکی", "سایز": "44", "قیمت (تومان)": "1,250,000", "موجودی": "3" }],
  "row_count": 128,
  "suggested_mapping": { "name": "نام کالا", "color": "رنگ", "size": "سایز", "price": "قیمت (تومان)", "stock": "موجودی" }
}
```

- `sample_rows` را به صورت جدول نشان بده تا کاربر مطمئن شود فایل درست خوانده شده.
- خطای رایج (422): «فایل در دسترس نیست. در گوگل شیت از Share ...» — متن را کامل نشان بده، راهنماست.

**مرحله ۳ — تطبیق ستون‌ها**
- لیست فیلدها: `GET /products/fields` → `[{key, label, required}]` (فقط `name` اجباری است)
- برای هر فیلد یک dropdown با گزینه‌های `headers` + گزینه‌ی «ندارم». مقدار اولیه از `suggested_mapping`.
- هر ستون فقط یک بار قابل انتخاب باشد.
- ستون‌هایی که به هیچ فیلدی وصل نشده‌اند هم ذخیره می‌شوند و ربات از آن‌ها استفاده می‌کند (مثل «جنس»)؛ این را به کاربر بگو تا نگران نباشد.
- ذخیره:
  - گوگل شیت: `PUT /products/sheet` با `{"url": "...", "column_mapping": {...}}`
  - فایل: `POST /products/file` با `multipart`: فیلد `file` (همان فایل) + فیلد `column_mapping` (رشته‌ی JSON)
- پاسخ هر دو: همان `SourceOut` بالا.

**اگر وصل است:**
- کارت وضعیت: نوع منبع، تعداد محصول، «آخرین به‌روزرسانی: ۳ دقیقه پیش»
- `last_error` مقدار دارد → کادر هشدار با همان متن. (ربات تا رفع مشکل از آخرین نسخه‌ی سالم استفاده می‌کند؛ این را هم بگو.)
- دکمه‌ی «به‌روزرسانی الان» (فقط گوگل شیت): `POST /products/sync`
- دکمه‌ی «تغییر ستون‌ها»: دوباره مرحله ۲ و ۳ با همان URL
- دکمه‌ی «قطع اتصال»: `DELETE /products/source` (محصولات هم پاک می‌شوند؛ تأیید بگیر)
- جدول محصولات: `GET /products?offset=0&limit=50` → `{items, total}`؛ جستجو: `GET /products?q=مانتو`
- `stock: null` یعنی موجودی نامشخص؛ `0` یعنی ناموجود.

### ۴.۵ تست ربات (Playground)

یک رابط چت ساده که کاربر قبل از روشن کردن ربات، خودش جای مشتری سوال بپرسد. **هیچ‌چیز ذخیره نمی‌شود** و کار می‌کند حتی وقتی ربات خاموش است.

`POST /playground/chat`

```json
{
  "messages": [
    { "role": "customer", "text": "سلام، مانتو مشکی ۴۴ دارید؟" },
    { "role": "bot", "text": "بله عزیزم موجوده، ۱,۲۵۰,۰۰۰ تومان" },
    { "role": "customer", "text": "ارسال به شیراز چقدره؟" }
  ]
}
```

- **تاریخچه را فرانت نگه می‌دارد** و هر بار کل آن را می‌فرستد (حداکثر ۳۰ پیام؛ آخرین پیام باید از `customer` باشد).
- پاسخ:

```json
{
  "reply": "با پست پیشتاز ۳ تا ۵ روز کاری میرسه، هزینه‌اش ۸۵ هزار تومانه.",
  "unanswered": false,
  "handoff_reason": null,
  "product_lookups": [{ "tool": "search_products", "arguments": {"query": "مانتو"}, "result": {"matches": [...]} }],
  "ai_ready": true
}
```

- `unanswered: true` → زیر جواب یک برچسب نشان بده: «در دایرکت واقعی، این سوال به شما ارجاع داده می‌شود» + لینک «افزودن این اطلاعات» (به صفحه‌ی اطلاعات).
- `product_lookups` خالی نیست → یک بخش جمع‌شونده «ربات این محصولات را بررسی کرد» (برای اعتمادسازی عالی است).
- دکمه‌ی «شروع دوباره» = پاک کردن تاریخچه.
- پاسخ ممکن است ۲ تا ۱۰ ثانیه طول بکشد؛ حالت «در حال نوشتن...» لازم است.

```json
        "reason": "مشتری فاکتور رسمی می‌خواهد",
        "question": "سلام\nفاکتور رسمی برای شرکت میدید؟",
        "resolved_at": null,
        "resolved_by": null
      },
      "last_message": { "id": "…", "sender": "bot", "text": "…", "unanswered": true, "created_at": "…" }
    }
  ],
  "total": 3
}
```

- `customer_username` ممکن است `null` باشد → «مشتری» + چند رقم آخر `customer_igsid` نشان بده.
- لینک پروفایل مشتری: `https://instagram.com/{customer_username}`
- `handoff.status == "open"` → نشان قرمز «منتظر جواب شما»؛ `bot_paused` → نشان «ربات متوقف».
- `handoff` برای گفتگویی که هرگز ارجاع نشده `null` است.

**جزئیات گفتگو:** `GET /conversations/{id}` → همان فیلدها + `messages` (قدیمی به جدید، ۲۰۰ پیام آخر)

سه نوع فرستنده، سه ظاهر متفاوت:

| `sender` | کیست | ظاهر پیشنهادی |
|---|---|---|
| `customer` | مشتری | سمت راست (RTL)، رنگ خنثی |
| `bot` | ربات | سمت چپ، رنگ اصلی + آیکون ربات |
| `owner` | خود صاحب پیج از اینستاگرام | سمت چپ، رنگ متفاوت + برچسب «شما» |

پیام ربات با `unanswered: true` → برچسب «ربات جواب را نمی‌دانست».
پیام‌هایی مثل `[image]` یا `[audio]` یعنی مشتری عکس/ویس فرستاده؛ به شکل آیکون نشان بده.

**کنترل ربات برای همین مشتری:**
- «توقف ربات برای این مشتری»: `POST /conversations/{id}/pause` با `{"minutes": 120}` یا `{}` (تا وقتی دستی ادامه داده شود)
- «ادامه‌ی پاسخ‌گویی ربات»: `POST /conversations/{id}/resume`
- وقتی صاحب پیج خودش از اینستاگرام جواب می‌دهد، ربات **خودکار** برای آن مشتری متوقف می‌شود (مدتش در تنظیمات)؛ `bot_paused_until` را به شکل «ربات تا ساعت ۱۴:۳۰ ساکت است» نشان بده.

> ارسال پیام از داخل پنل در این نسخه نیست؛ صاحب پیج از خود اینستاگرام جواب می‌دهد. دکمه‌ی «جواب در اینستاگرام» به `instagram_url` لینک شود (اگر `null` بود، دکمه را نشان نده).

**به‌روزرسانی زنده:** WebSocket نداریم. هر ۱۰–۱۵ ثانیه لیست (و گفتگوی باز) را دوباره بگیر، فقط وقتی تب مرورگر فعال است.

### ۴.۷ ارجاع‌شده به شما (دایرکت‌هایی که ربات جوابشان را نمی‌دانست)

وقتی ربات جواب سوالی را در اطلاعات فروشگاه پیدا نکند، به مشتری «پیام جواب ندادن» را می‌فرستد و گفتگو را **به مدیر ارجاع می‌دهد**. این صفحه لیست مشتری‌هایی است که **الان منتظر جواب مدیر هستند**؛ مهم‌ترین صفحه‌ی روزمره‌ی پنل.

`GET /handoffs?status=open` (پیش‌فرض)

```json
{
  "items": [
    {
      "conversation_id": "…",
      "customer_igsid": "900000000000001",
      "customer_username": "neda_k",
      "instagram_url": "https://ig.me/m/neda_k",
      "last_customer_message_at": "2026-09-23T09:45:00Z",
      "handoff": {
        "status": "open",
        "handed_off_at": "2026-09-23T09:46:00Z",
        "reason": "مشتری فاکتور رسمی می‌خواهد",
        "question": "سلام\nفاکتور رسمی برای شرکت میدید؟",
        "resolved_at": null,
        "resolved_by": null
      }
    }
  ],
  "total": 1
}
```

- ترتیب: **قدیمی‌ترین اول** (مشتری‌ای که بیشتر منتظر مانده بالاست).
- `question`: چیزی که مشتری پرسیده. اگر مشتری در حین انتظار باز هم بنویسد، به همین متن اضافه می‌شود (ربات دوباره «پیام جواب ندادن» نمی‌فرستد).
- `reason`: توضیح کوتاه فارسی ربات درباره‌ی علت ارجاع.
- مدت انتظار را از `handed_off_at` حساب کن و نشان بده: «۱۴ دقیقه است منتظر است». بعد از ۱ ساعت رنگ هشدار.

**برای هر مورد:**
1. **«جواب در اینستاگرام»** (دکمه‌ی اصلی) → باز کردن `instagram_url` در تب جدید. وقتی مدیر در اینستاگرام جواب بدهد، **ارجاع خودکار بسته می‌شود** و در بازخوانی بعدی از لیست حذف می‌شود.
2. **«دیدن گفتگو»** → صفحه‌ی گفتگو (`conversation_id`)
3. **«بستن»** (مثلاً تلفنی جواب داده) → `POST /handoffs/{conversation_id}/resolve` (204)
4. **«افزودن به اطلاعات ربات»** (ثانویه) → فرم FAQ با `title` = سوال، تا دفعه‌ی بعد ربات خودش جواب بدهد.

**تب «بسته‌شده‌ها»:** `GET /handoffs?status=resolved` (جدیدترین اول). `resolved_by`:
- `owner_reply` → «پاسخ داده‌شده در اینستاگرام»
- `manual` → «بسته‌شده توسط شما»

**اعلان:** لیست را هر ۱۵–۳۰ ثانیه بازخوانی کن (حتی وقتی کاربر در صفحه‌ی دیگری است، فقط `GET /dashboard` و `open_handoffs`). وقتی عدد زیاد شد:
- عدد را در عنوان تب مرورگر نشان بده: `(2) پنل مزون مهسا`
- اگر کاربر اجازه داد، **Notification مرورگر**: «نِدا منتظر جواب شماست: فاکتور رسمی برای شرکت میدید؟»

> **فرق با «سوال‌های بی‌جواب» (بخش ۴.۸):** اینجا یعنی «یک مشتری منتظر توست» و با جواب دادن تمام می‌شود. آن‌جا یعنی «این اطلاعات در ربات نیست» و با اضافه کردن اطلاعات تمام می‌شود. یک سوال می‌تواند در هر دو باشد.

### ۴.۸ سوال‌های بی‌جواب (کمبود اطلاعات)

مهم‌ترین صفحه برای بهتر شدن ربات: سوال‌هایی که ربات جوابشان را در اطلاعات فروشگاه پیدا نکرد.

`GET /unanswered` (جدیدترین اول)

```json
[
  {
    "message_id": "…",
    "conversation_id": "…",
    "customer_username": "neda_k",
    "question": "سلام\nفاکتور رسمی برای شرکت میدید؟",
    "created_at": "2026-09-23T09:46:00Z"
  }
]
```

برای هر مورد سه دکمه:
1. **«افزودن به اطلاعات»** → فرم افزودن FAQ باز شود با `title` = متن سوال (پر شده) و `content` خالی. بعد از ذخیره (`POST /knowledge`)، خودکار `resolve` هم صدا زده شود.
2. **«دیدن گفتگو»** → صفحه‌ی گفتگو با `conversation_id`
3. **«نادیده گرفتن»** → `POST /unanswered/{message_id}/resolve` (204)

### ۴.۹ تنظیمات ربات

`GET /shop` و `PATCH /shop` (فقط فیلدهای تغییرکرده را بفرست)

| فیلد | نوع | UI |
|---|---|---|
| `name` | رشته (۱–۱۲۰) | اسم فروشگاه؛ ربات خودش را با این اسم معرفی می‌کند |
| `bot_enabled` | بولین | کلید روشن/خاموش |
| `tone` | `friendly` \| `formal` | دو گزینه: «صمیمی» / «رسمی» |
| `use_emoji` | بولین | «استفاده از ایموجی» |
| `fallback_message` | رشته (۱–۱۰۰۰) | «پیامی که ربات وقتی جواب را نمی‌داند می‌فرستد» |
| `forbidden_rules` | رشته (تا ۴۰۰۰) | «قوانین ربات» — مثال در placeholder: «هیچ‌وقت تخفیف نده. درباره‌ی رقبا حرف نزن.» |
| `handoff_pause_minutes` | عدد (۰ تا ۱۰۰۸۰) | «وقتی خودم جواب دادم، ربات چند دقیقه ساکت بماند» — ۰ یعنی ساکت نشود |

پیشنهاد: بعد از تغییر لحن، دکمه‌ی «امتحان در صفحه‌ی تست».

### ۴.۱۰ حساب کاربری

| کار | درخواست |
|---|---|
| تغییر رمز | `POST /me/password` با `{current_password, new_password}` (204؛ رمز اشتباه → 400) |
| حذف حساب | `DELETE /me` با body `{"password": "..."}` (204) — **همه‌چیز** پاک می‌شود؛ تأیید دو مرحله‌ای بگیر و بعد کاربر را خارج کن |

> `DELETE` با body: در `fetch` مشکلی نیست؛ در axios باید `axios.delete(url, { data: {...} })` بنویسی.

### ۴.۱۱ صفحه‌های عمومی (برای تأیید متا — الزامی)

این‌ها بدون لاگین باز می‌شوند و متا آدرسشان را می‌خواهد:
- `/privacy` — سیاست حریم خصوصی: چه داده‌ای از اینستاگرام می‌گیریم (پیام‌ها، یوزرنیم مشتری)، کجا نگه می‌داریم، چطور حذف می‌شود
- `/terms` — شرایط استفاده
- `/data-deletion` — راهنمای حذف داده: «از پنل ← حساب کاربری ← حذف حساب، یا ایمیل به ...»

پنل باید **نسخه‌ی انگلیسی** هم داشته باشد (یا حداقل صفحه‌های اصلی)، چون داور متا فارسی نمی‌خواند. ساده‌ترین راه: i18n از اول پروژه.

## ۱۰. پست‌های اینستاگرام (اضافه‌شده بعد از نسخه‌ی اول)

ربات وقتی محصولی را پیشنهاد می‌دهد، پست اینستاگرامی همان محصول را هم به‌صورت کارت پست برای مشتری می‌فرستد. پیاده‌سازی پنل انجام شده؛ این بخش برای مرجع است.

| کار | درخواست |
|---|---|
| پست‌ها و محصولات وصل‌شده به هر پست | `GET /instagram/posts` → `{synced_at, total, products_without_post, items: [{permalink, caption, preview_url, media_type, posted_at, products}]}` |
| خواندن دوباره از اینستاگرام | `POST /instagram/posts/sync` (همان خروجی؛ پیج وصل نباشد → 400، خطای اینستاگرام → 502) |

- **تست ربات:** پاسخ `POST /playground/chat` حالا `posts: [{permalink, caption, preview_url}]` هم دارد؛ هر کدام یک کارت پست زیر جواب ربات (`components/PostCard.tsx`).
- **صندوق پیام:** پستی که ربات فرستاده یک پیام ربات با متن `[پست] <permalink>` است؛ به‌جای حباب متن، کارت پست نمایش داده می‌شود (`sharedPostUrl`).
- **فایل محصولات:** فیلد جدید `post_url` («لینک پست اینستاگرام») خودکار در مرحله‌ی تطبیق ستون‌ها ظاهر می‌شود (از `GET /products/fields`).
- **تست ربات، جستجوی محصول:** کلید جایگزین‌ها در `product_lookups` حالا `other_in_stock_variants` است (فقط رنگ/سایزهای موجود).

## ۱۱. تلگرام، کیف پول، کاتالوگ محصولات و «یاد دادن به جواب» (مهر ۱۴۰۵)

> **وضعیت (۱۰ مهر ۱۴۰۵):** همه‌ی این بخش در پنل پیاده شده است: صفحه‌های `pages/Telegram.tsx`، `pages/Billing.tsx`، `pages/ForgotPassword.tsx`، `pages/ResetPassword.tsx`؛ کاتالوگ و «به جواب یاد بده» در `pages/Products.tsx` و `components/teach.tsx`؛ کادر جواب در صندوق پیام؛ متن‌ها در `i18n/launch.fa.ts` و `launch.en.ts`. این بخش برای مرجع و توسعه‌ی بعدی است.

بک‌اند حالا چندکاناله است: **تلگرام اولین کانال فعال است** و اینستاگرام تا تأیید متا خاموش است (کدش سر جایش است). همه‌ی endpointها زیر `/api/v1` و در `docs/openapi.json` هستند؛ تایپ‌ها را دوباره بساز (بخش ۹).

### ۱۱.۱ تغییرهای سازگار با نسخه‌ی فعلی پنل
- **گفتگوها** (`GET /conversations`، `/conversations/{id}`، `/handoffs`): فیلدهای تازه‌ی `channel` (`instagram` | `telegram`)، `customer_id`، `customer_name` و `chat_url` (لینک باز کردن چت در اپ همان کانال). `customer_igsid` و `instagram_url` برای سازگاری مانده‌اند؛ از این به بعد از `chat_url` استفاده کن. فیلتر تازه: `?channel=telegram`. آیکن کانال کنار هر گفتگو لازم است.
- **جواب دادن از پنل:** `POST /conversations/{id}/reply` با `{text}`. پیام در همان کانال برای مشتری می‌رود، ربات در آن گفتگو کنار می‌کشد و ارجاع بسته می‌شود. اگر کانال وصل نباشد یا از پیام مشتری بیش از ۲۴ ساعت گذشته باشد (اینستاگرام و تلگرام بیزینس)، پاسخ `409` با پیام فارسی است.
- **اینستاگرام:** `GET /instagram` فیلد `available` دارد. وقتی `false` است، دکمه‌ی اتصال را با متن «به‌زودی» غیرفعال کن (`GET /instagram/connect-url` در این حالت `503` می‌دهد).
- **داشبورد:** در `setup` این فیلدها اضافه شده‌اند: `instagram_available`، `telegram_available`، `telegram_owner_linked`، `telegram_custom_bot`، `telegram_business`، `telegram_channels`. فیلد تازه‌ی `wallet` (`{enabled, balance_toman, low_balance, plan}`) و `pending_proposals` هم هست. چک‌لیست راه‌اندازی باید قدم‌های تلگرام را نشان بدهد.
- **فروشگاه:** `GET /shop` فیلد `slug` دارد (شناسه‌ی عمومی در لینک تلگرام).

### ۱۱.۲ صفحه‌ی «تلگرام» (تازه)
| کار | درخواست |
|---|---|
| وضعیت کامل | `GET /telegram` → `{available, enabled, shared_bot_username, shop_link, admins[], custom_bot, custom_bot_allowed, business{connected, enabled, can_reply}, business_allowed, business_bot_username, channels[], plan}` |
| خاموش/روشن کردن کل تلگرام | `PATCH /telegram` با `{enabled}` |
| وصل کردن اکانت تلگرام صاحب فروشگاه | `POST /telegram/link` → `{url, expires_at}`. لینک را دکمه کن و QR آن را هم نشان بده (روی گوشی باز شود). ۳۰ دقیقه و یک بار اعتبار دارد. |
| حذف اکانت وصل‌شده | `DELETE /telegram/admins/{id}` |
| ربات اختصاصی (پلن حرفه‌ای به بالا) | `PUT /telegram/custom-bot` با `{token}` (از @BotFather)؛ خطای فارسی با `422`. حذف: `DELETE /telegram/custom-bot` |
| قطع تلگرام بیزینس | `DELETE /telegram/business` |
| حذف کانال | `DELETE /telegram/channels/{id}` |

محتوای صفحه، به ترتیب:
1. **لینک فروشگاه** (`shop_link`) با دکمه‌ی کپی و QR، با این توضیح: «این لینک را در بیو اینستاگرام، کانال و استوری بگذارید؛ مشتری با زدنش مستقیم با دستیار فروشگاه شما حرف می‌زند».
2. **اتصال اکانت تلگرام خودتان:** «خبرِ مشتری‌هایی که منتظر شما هستند همان‌جا می‌آید، همان‌جا جواب می‌دهید، و با پیام متنی یا صوتی به ربات محصول یاد می‌دهید».
3. **کانال تلگرام:** راهنمای «ربات (`@{shared_bot_username}`) را ادمین کانالتان کنید» و لیست `channels`.
4. **ربات اختصاصی:** راهنمای ۳ قدمی BotFather (`/newbot` → نام → کپی توکن) و فیلد توکن. اگر `custom_bot_allowed=false` است، قفل باشد با لینک به صفحه‌ی کیف پول/پلن.
5. **تلگرام بیزینس:** راهنما: «تلگرام پرمیوم ← Settings ← Telegram Business ← Chatbots ← `@{business_bot_username}` را اضافه کنید و اجازه‌ی Reply to messages بدهید». پیش‌نیاز این است که اکانت در قدم ۲ وصل شده باشد. اگر `business_allowed=false` است، قفل باشد.

### ۱۱.۳ صفحه‌ی «محصولات»، کاتالوگ داخل جواب
همه‌ی محصولات، از هر راهی که آمده باشند، در یک لیست هستند. هر محصول `origin` دارد:
`manual` (دستی)، `sheet` (گوگل شیت زنده)، `file` (اکسل)، `teach` (یاد گرفته از متن، صوت، داک یا لینک)، `telegram_post` (پست کانال). یک برچسب کوچک برای هر کدام نشان بده.

| کار | درخواست |
|---|---|
| لیست + جستجو + فیلتر | `GET /products?q=&origin=&stock=in_stock\|out_of_stock\|unknown&offset&limit` |
| خلاصه برای بالای صفحه | `GET /products/summary` → `{total, in_stock, out_of_stock, stock_unknown, by_origin, limit}` |
| افزودن دستی | `POST /products` با `{name, sku?, category?, color?, size?, price? (تومان), stock?, description?, image_url?, post_url?}` |
| ویرایش سریع (قیمت، موجودی…) | `PATCH /products/{id}` فقط با فیلدهای تغییرکرده؛ `null` یعنی پاک کردن |
| حذف | `DELETE /products/{id}` |

- `editable=false` یعنی ردیف از گوگل شیت زنده است: ویرایش و حذف ندارد (سرور `409` می‌دهد) و باید آیکن قفل با توضیح «در خود شیت تغییر دهید» داشته باشد.
- **«جواب از این محصول چه می‌داند»:** فیلد `bot_view` دقیقاً همان چیزی است که ربات می‌بیند. آن را در جزئیات محصول نشان بده.
- ویرایش سریع موجودی (دکمه‌های + و −) خیلی کاربردی است.
- حذف منبع شیت (`DELETE /products/source`) فقط ردیف‌های همان شیت را پاک می‌کند، نه محصولات دستی و بقیه.

### ۱۱.۴ «به جواب یاد بده» (تازه؛ دل این نسخه)
یک کادر بزرگ بالای صفحه‌ی محصولات (یا صفحه‌ی جدا): «هر جور راحتید توضیح بدهید». سه ورودی:

| ورودی | درخواست |
|---|---|
| متن آزاد (لیست قیمت، «فلان تموم شد»، شرایط ارسال، متن کپی‌شده) | `POST /teach/text` با `{text}` |
| لینک گوگل داک، گوگل شیت یا فایل درایو | `POST /teach/url` با `{url}` |
| فایل (PDF، Word، Excel، CSV، عکس لیست قیمت) | `POST /teach/file` (multipart، فیلد `file`) |

هر سه یک **پیشنهاد** (proposal) برمی‌گردانند و هنوز چیزی تغییر نکرده است:
```
{id, status: "pending", summary, preview, changes: {
   products: [{action: "create"|"update"|"delete", product_id, before, fields, locked}],
   knowledge: [{section, title, content, mode: "replace"|"add"}],
   questions: [...], sheet?: {url, mapping, rows}
}}
```
- پیش‌نمایش را با تیک برای هر ردیف نشان بده: برای `update`، مقدار `before` در مقابل `fields` (مثلاً «قیمت: ۸۹۰٬۰۰۰ ← ۹۵۰٬۰۰۰»). `locked=true` یعنی ردیف گوگل شیت است و اعمال نمی‌شود. `questions` سوال‌های هوش مصنوعی از صاحب فروشگاه است. اگر وقت نداری، فیلد `preview` همان متن آماده‌ای است که ربات تلگرام نشان می‌دهد.
- **ثبت:** `POST /teach/proposals/{id}/apply` با `{skip_products: [index…], skip_knowledge: [index…]}` (اندیس ردیف‌هایی که تیکشان برداشته شده). **رد:** `POST /teach/proposals/{id}/discard`.
- **لیست:** `GET /teach/proposals?status=pending`. پیشنهادهایی که صاحب فروشگاه از تلگرام فرستاده (صوت، عکس، پست فورواردشده) هم اینجا هستند؛ عددش در داشبورد `pending_proposals` است.
- **برگرداندن:** `POST /teach/proposals/{id}/undo` محصولاتی را که یک پیشنهادِ ثبت‌شده اضافه کرده حذف می‌کند (مثلاً پست کانالی که اشتباهی محصول تشخیص داده شده).
- خطاها `422` با پیام فارسی‌اند (لینک غیر گوگل، فایل خراب، کیف پول خالی)، و `502` یعنی سرویس هوش مصنوعی جواب نداد.

### ۱۱.۵ صفحه‌ی «کیف پول و پلن» (تازه، مسیر `/billing`)
| کار | درخواست |
|---|---|
| موجودی، پلن، تعرفه‌ها | `GET /billing` → `{enabled, balance_toman, low_balance, plan, plan_renews_at, plan_next, plans: [{key, label, monthly_fee_toman, features}], pricing: {..., typical_answer_toman}, topup_available, topup_min_toman, topup_max_toman}` |
| تاریخچه | `GET /billing/entries?kind=&offset&limit` → `{items: [{kind: topup\|usage\|plan_fee\|bonus\|adjustment, amount_toman, balance_after_toman, description, created_at}], total}` |
| شارژ | `POST /billing/topup` با `{amount_toman}` → `{payment_url}`؛ مرورگر را به آن بفرست. بعد از پرداخت، کاربر به `/billing?payment=success&ref=…` یا `/billing?payment=failed` برمی‌گردد؛ پیام موفقیت یا خطا نشان بده. |
| تغییر پلن | `POST /billing/plan` با `{plan}`. ارتقا فوری است و هزینه‌ی ماه از کیف پول کم می‌شود (اگر موجودی کم باشد `402` با پیام فارسی). کاهش پلن آخر ماه اعمال می‌شود (`plan_next`). |

- منطق قیمت‌گذاری: هر جواب ربات به اندازه‌ی مصرف هوش مصنوعی‌اش از کیف پول کم می‌شود. `typical_answer_toman` را برای حس عدد نشان بده: «هر جواب حدود X تومان». پلن‌های بالاتر فقط ماهانه‌ی ثابت اضافه دارند.
- اگر `topup_available=false` است (درگاه هنوز وصل نشده)، به جای دکمه‌ی پرداخت بنویس «برای شارژ با پشتیبانی تماس بگیرید».
- وقتی `low_balance` است، یک نوار هشدار بالای همه‌ی صفحه‌های پنل لازم است.

### ۱۱.۶ فراموشی رمز عبور (تازه)
- **صفحه‌ی «فراموشی رمز»** (لینکش زیر فرم ورود): `POST /auth/password/forgot` با `{email}`. همیشه `202` با یک `message` ثابت برمی‌گردد (برای امنیت). همان پیام را نشان بده.
- **صفحه‌ی `/reset-password?token=...`** (لینکی که در ایمیل می‌آید): فرم رمز جدید (حداقل ۸ کاراکتر) → `POST /auth/password/reset` با `{token, new_password}` → `204`، بعد برو به صفحه‌ی ورود. توکن نامعتبر، منقضی یا استفاده‌شده `400` با پیام فارسی می‌دهد.

### ۱۱.۷ سایت عمومی
- **واتس‌اپ:** کاشی واتس‌اپ در `components/site/channels.tsx` کامنت شد (API واتس‌اپ شماره‌های ایران را قبول نمی‌کند). اگر متن‌های landing جایی هنوز از واتس‌اپ یا اتصال اینستاگرام حرف می‌زنند، بازنویسی‌شان با تصمیم شما و مهرشاد است.
- در `CHANNELS`، `telegram` حالا `live: true` و `instagram` `live: false` است.
